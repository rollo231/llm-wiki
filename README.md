# LLM 위키

[카파시의 gist](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f)가 제안한 **LLM 위키**
패턴으로 만드는 개인 지식 베이스입니다. [Obsidian](https://obsidian.md)으로 읽고, LLM 에이전트가 쓰고
관리합니다.

> Obsidian 은 IDE, LLM 은 프로그래머, 위키는 코드베이스.

질문할 때마다 원본에서 답을 다시 찾아내는 대신, 에이전트가 자료를 읽을 때마다 **위키에 통합해 둡니다.**
요약·교차참조·모순 표시가 이미 되어 있으므로 위키는 자료와 질문이 더해질수록 두꺼워집니다.
사람은 자료를 고르고 질문하며, 에이전트는 나머지 — 요약·교차참조·정리·기록 — 를 맡습니다.

지금은 **패스트캠퍼스 AI 데이터 엔지니어링 강의** 하나에서 출발합니다.

## 구조

```
llm-wiki/
├─ CLAUDE.md     # 에이전트가 따르는 스키마
├─ index.md      # 모든 페이지 목록
├─ log.md        # 활동 기록 (시간순, 추가만)
├─ raw/          # 원본 자료 — gitignore, 불변
└─ wiki/
   ├─ sources/   # 자료 요약
   ├─ entities/  # 도구·제품·조직·사람·강의
   ├─ concepts/  # 개념·방법·주제
   └─ notes/     # 비교·분석·종합
```

`raw/` 는 gitignore 대상이라 이 repo 에 올라가지 않습니다. 출처는 각 source 페이지의 인용에 남습니다.
전체 규칙은 [`CLAUDE.md`](CLAUDE.md)를 보세요.

## 작업

- **인제스트** — 자료가 `raw/` 에 들어오면 에이전트가 읽고, 핵심을 논의하고, source 페이지를 쓰고,
  관련 entity·concept 페이지를 고치고, `index.md` 와 `log.md` 를 갱신합니다.
- **질의** — 에이전트가 `index.md` 부터 읽고 링크를 따라가 **인용과 함께** 답합니다. 가치 있는 답은
  note 페이지로 남겨 탐색도 쌓이게 합니다.
- **린트** — 요청하면 모순·낡은 주장·고아 페이지·빠진 교차참조·자료 공백을 점검합니다.

## 시작하기

1. 이 폴더를 [Obsidian](https://obsidian.md) 볼트로 엽니다.
2. `raw/` 에 자료를 넣습니다.
3. 에이전트에게 인제스트를 요청하고, 결과 커밋을 검토합니다.
