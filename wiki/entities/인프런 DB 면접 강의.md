## 자료의 형식: 등급 루브릭

[[인프런 Java 면접 강의]]와 같다. 질문 하나는 "Main Question" 또는 "Follow-Up Question" 표지 한 쪽과 등급별 답변 쪽으로 이뤄지고, Bronze(Lv.1)·Silver(Lv.2)에는 무엇이 빠졌는지 "이유"가 붙는다. Gold(Lv.3)에는 이유가 없다.

- 42문항 모두 Silver와 Gold가 있다. 세 등급이 다 있는 문항 16개, Silver + Gold 26개. Bronze + Gold만 있는 문항은 없다.
- Silver의 "이유"가 지적하는 빈 곳은 대개 메커니즘 이름이다(언두 영역, 넥스트 키 락, read-modify-write, Binlog → Relay log → SQL Thread, active/idle/pending). Java 강의보다 "구체적 이름을 대라"는 쪽으로 기운다. 이 관찰은 위키가 한 것이다.
- 운영 질문(Section 6·7)의 Gold는 "첫째·둘째·셋째" 순서로 대응 절차를 말한다. 면접에서 절차를 순서대로 말하는 틀로 쓸 만하다.

## 자료 평가

- 쓸모: 꼬리 질문의 사슬(격리 수준 → 이상 현상 → 해결 → MVCC → InnoDB의 Phantom, 인덱스 → B-Tree → 클러스터링 → 세컨더리 조회)이 면접의 실제 흐름을 잘 보여 준다. 운영 질문(슬로우 쿼리, 장애 대응 순서, 모니터링 지표)은 절차를 순서대로 말하는 연습 틀로 쓸 만하다.
- 결함: 외부 검증(2026-09-28, MySQL 8.4·8.0 매뉴얼 · PostgreSQL 문서 · Berenson et al. 1995 · Jakarta Persistence 3.1 · HikariCP 문서·소스 · Brewer 2012 · Kleppmann 2015·2016 대조) 33건 가운데 틀림 7 · 낡음 1 · 단서 필요 18 · 맞음 7이다. 틀림은 트랜잭션·락·인덱스(Section 2~4)에 몰려 있고, 운영(Section 6·7)의 절차와 지표는 대체로 맞다. 가장 큰 문제는 MySQL InnoDB의 동작을 일반론처럼 말하는 것이다. Lost Update를 격리 수준으로 못 막는다는 p38은 InnoDB RR에서만 사실이고, SERIALIZABLE·스냅숏 격리·PostgreSQL RR은 막는다. 반대로 p52의 인덱스 동작은 InnoDB가 아니라 MyISAM·PostgreSQL 구조를 설명해, 같은 자료의 p55와 어긋난다.

## 위키와의 연결

이 위키의 다른 자료와 만나는 곳이다. 자료에는 없고 위키가 이은 연결이다.

- [[AI DE 강의 3-01 스키마 중심 설계와 RDBMS]] · [[AI DE 강의 3-02 RDBMS의 한계와 NoSQL]]이 같은 주제(ACID, 정규화, RDBMS의 확장 비용, NoSQL 네 타입)를 데이터 엔지니어링 쪽에서 다룬다([[관계형 데이터베이스]] · [[NoSQL]]).
- CAP와 복제는 [[AI DE 강의 4-02 CAP 정리와 분산 시스템의 한계]] · [[AI DE 강의 4-03 고가용성·복제·합의]]가 더 깊게 다룬다([[CAP 정리]] · [[복제]]).
- 커넥션 풀 크기와 스레드 수의 관계는 [[Java 면접 4 동시성 이슈]]의 Spring MVC 질문과 이어진다([[스레드 풀]] · [[커넥션 풀]]).
- 데드락은 Java 쪽 [[데드락 재현과 해법]]과 원인·해법이 같다.
- 분산 락과 캐시는 [[Redis]]를 전제한다.
