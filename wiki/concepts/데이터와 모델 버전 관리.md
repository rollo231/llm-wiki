# 데이터와 모델 버전 관리

코드를 git으로 관리하듯 **학습에 쓴 데이터와 모델도 버전으로 관리해 결과를 재현할 수 있게 하는 것.**
[[AI DE 강의 1-02 AI DE 마인드셋 Latency와 Versioning]]은 이것을 AI DE의 두 마인드셋 중 하나로 든다.

## 재현성의 3요소

| 요소 | 방법 |
|---|---|
| 데이터 스냅샷 | 학습을 시작하는 순간의 데이터를 사진 찍듯 저장 |
| 환경 고정 | Docker 컨테이너, Conda 가상 환경 |
| 랜덤 시드 | 시드 고정 |

## Part 1에 흩어진 구현 수단

강의는 "버전 관리"를 한 곳에서 정리하지 않지만, 같은 요구가 여러 강의에서 서로 다른 도구로 나온다.
*(위키의 종합)*

| 수단 | 무엇을 되돌리나 | 출처 |
|---|---|---|
| 트랜잭션 로그와 Time Travel | 테이블의 과거 시점 | [[Delta Lake]] |
| ELT의 원본 보존 | 로직이 바뀌면 원본에서 다시 계산 | [[ETL과 ELT]] |
| 오프셋 되감기(replay) | 이벤트 스트림을 과거 위치부터 재처리 | [[Apache Kafka]] |
| 스키마 레지스트리 | 메시지 구조의 버전 | [[스키마 진화]] |
| 재학습 파이프라인의 데이터셋 버전 | 어떤 데이터로 어떤 모델을 학습했나 | [[AI DE 강의 1-13 Skew와 Drift]] |
| 데이터 계보(lineage) | 모델이 어떤 데이터를 학습했는지 증명 | [[데이터 거버넌스와 카탈로그]] |

## 빈칸

- 데이터·모델 버전 관리 전용 도구(예: DVC, MLflow의 모델 레지스트리)는 Part 1에 이름이 나오지 않는다.
- "데이터 스냅샷"을 대용량에서 어떻게 싸게 만드는지(복사 vs 메타데이터 포인터)는 다루지 않는다. Delta Lake의
  Time Travel이 후자의 예다.
