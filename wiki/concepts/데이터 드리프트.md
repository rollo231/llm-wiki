# 데이터 드리프트

코드와 파이프라인은 그대로인데 **현실이 바뀌어** 모델이 학습한 과거와 서빙 시점의 데이터가 어긋나는 현상.
모델은 "과거를 비춘 거울"이므로 **성능 저하는 버그가 아니라 시간의 함수**다([[AI DE 강의 1-13 Skew와 Drift]]).

## 두 종류

| | Data Drift (공변량 변화) | Concept Drift |
|---|---|---|
| 무엇이 바뀌나 | 입력 분포 P(X) | 입력과 정답의 관계 P(Y\|X) |
| 강의의 예 | 코로나19: 마스크 대량 구매가 희귀한 사기 패턴(2019)에서 생존을 위한 정상 행동(2020)으로 → 정상 거래 오탐지 | 스팸: "당첨! 100% 무료"에서 "CJ대한통운 배송 안내입니다" 같은 일상 문장 + 악성 링크로 → 스팸을 정상으로 오판 |
| 징후 | 새로운 패턴, 특정 층·시간대 비중 급변, 계절성 | 입력은 비슷해 보이는데 정답 기준이 바뀜 |

Concept drift의 유형: **급격한**(락다운) · **점진적**(인플레이션) · **주기적**(블랙프라이데이·계절).

## 원인

| 외부 | 내부 |
|---|---|
| 팬데믹·사회적 이슈 | 마케팅 캠페인으로 신규 사용자층 유입 |
| 경기 변동·인플레이션 | UI/UX 개편으로 클릭 로그 패턴 변화 |
| 규제·정책 변화 | 가격 정책·서비스 변경 |
| 계절성 | 데이터 파이프라인 변경(로깅 수정, 단위 cm → m) |

내부 요인의 마지막 줄은 엄밀히 **세상이 아니라 우리가 바꾼 것**이다 — Zinkevich의 스큐 원인 분류로 보면 "학습·서빙
파이프라인의 데이터 처리 불일치"에 해당한다. *(위키의 관찰)* 호환성 검사가 못 잡는 이유 → [[스키마 진화]] · [[학습-서빙 스큐]]

## 용어

같은 "드리프트"가 자료마다 다른 축으로 쓰인다. *(위키의 정리)*

| 용어 | 뜻 | 축 | 출처 |
|---|---|---|---|
| Data Drift / Concept Drift | P(X)의 변화 / P(Y\|X)의 변화 | **무엇이 바뀌었나** | [[AI DE 강의 1-13 Skew와 Drift]] |
| Model Drift | 예측 성능 저하(입력 분포 변화인 Data Drift와 나란히 둠) | **무엇으로 관측되나** | [[AI DE 강의 2-02 MLOps와 ML 생애주기]] |
| 스큐 vs 드리프트 (분포 비교의 뜻) | 스큐 = 학습 vs 서빙 분포, 드리프트 = 시간에 따른 변화 | **무엇과 비교하나** | TFDV·Vertex AI → [[학습-서빙 스큐]] |
| Context Drift / Prompt Drift | 검색·컨텍스트 품질 저하 / 프롬프트 수정 누적으로 동작 변화 | LLM 시스템 | [[AI DE 강의 2-03 LLMOps]] — 정립된 용어가 아니다 → [[LLMOps]] |

마지막 줄의 두 용어는 벤더 블로그마다 정의가 다르고, AWS의 LLM 드리프트 가이드도 data drift·concept drift 두 가지로만
나눈다. 강의의 정의는 강의의 것으로 읽는다.

[[AI DE 강의 2-06 Training-Serving Skew 예방]]은 Data Drift를 학습-서빙 스큐의 **원인** 중 하나로 든다. Google의 「Rules of
Machine Learning」도 "학습과 서빙 사이의 데이터 변화"를 스큐의 원인으로 드는 정의라 이것과 맞는다. → [[학습-서빙 스큐]]

## 감지

기준 분포(학습 데이터)와 실시간 분포(서빙 데이터)를 통계로 비교한다. 강의가 드는 지표: **PSI**(Population
Stability Index), **KL Divergence**, **Chi-square**, **KS Test**.

⚠️ 학습 vs 서빙 분포 비교를 "드리프트 감지"로 부르는 것은 **강의의 용법**이다. 위 용어 표의 TFDV·Vertex AI 용법에서는
이 비교가 **스큐 감지**이고, 드리프트 감지는 **시간 구간끼리**(span N vs N+1) 비교한다. → [[학습-서빙 스큐]]

### PSI 임계치 — 강의 정정

- 강의는 재학습 트리거로 **"PSI > 0.2"**를 든다.
- 널리 쓰이는 관례는 **PSI < 0.1 변화 적음 · 0.1~0.25 중간 · 0.25 이상 유의미한 변화(조치 필요)**이고, 이 기준 자체가
  통계적 오류율 근거 없이 쓰이는 **경험칙**이다(Lewis 1994에서 유래). 0.2는 이 관례에 없는 값이다.
  [Yurdakul & Naranjo (2020), *Journal of Risk Model Validation* 14(4),
  https://files.wmich.edu/s3fs-public/attachments/u730/2022/PSIfinal.pdf , 2026-09-14 확인]
- 경험칙이므로 피처마다·도메인마다 임계치를 **과거 데이터로 보정**해야 한다. *(위키 메모)*

## 대응 — 자동 재학습

**트리거** — 드리프트 임계치 초과, 성능 지표(Accuracy·F1) 하락, 정기 스케줄·시즌 이벤트.

**5단계** — 데이터 수집(최신 피처·라벨, 품질·스키마 검증, 데이터셋 버전) → 학습(재현 가능한 환경) → 평가
(Champion vs Challenger, 공정성 체크) → 배포(카나리·블루-그린, 섀도우 모드, 자동 롤백) → 관측(피드백 루프).

**안전장치** — 무분별한 재학습을 막는 **쿨다운 기간**, 고위험 모델의 **사람 승인**.

**준비 과제** — 학습 데이터의 기준 분포를 저장해 두기, 주요 피처의 PSI 추이 대시보드와 알림, 재학습 절차·승격 규칙·
롤백을 담은 플레이북.

## 빈칸

- 라벨 분포 자체의 변화(P(Y))는 다루지 않는다.
- 정답 라벨이 늦게 도착할 때(예: 사기 여부가 몇 주 뒤 확정) 성능 저하를 어떻게 감지하는지는 다루지 않는다. Part 2의
  [[AI DE 강의 2-04 ML 데이터 파이프라인]]도 "라벨 지연 = 학습 주기 연장"까지만 말한다.
