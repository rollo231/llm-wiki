# 함수형 프로그래밍

순수 함수와 불변성을 기반으로, 함수를 값처럼 다루며 프로그램을 짜는 패러다임. 자료는 세 기둥으로 정리한다([[Java 면접 6 람다와 스트림]] p111–113).

1. **순수 함수** — 같은 입력에 항상 같은 출력을 내고, 바깥 상태를 바꾸지 않는다. 그래서 부수 효과가 없다.
2. **불변성** — 데이터를 제자리에서 고치지 않고, 바꿔야 하면 새 데이터를 만든다.
3. **일급 함수** — 함수를 변수에 담고, 인자로 넘기고, 반환값으로 돌려줄 수 있다.

## 위반 예시 (p114 코드 슬라이드)

자료의 이미지 슬라이드가 두 가지 위반을 보여 준다.

- `greet(name)`이 바깥에 선언된 `List<String> log`에 이름을 추가한다 → **순수 함수 위반**, 외부 상태를 건드린다.
- `addName(list, name)`이 인자로 받은 리스트에 직접 `add`한다 → **불변성 위반**, 원본 데이터를 수정한다.

## 데이터 엔지니어에게 익숙한 모습

함수형의 원칙은 데이터 파이프라인 설계 원칙과 거의 같은 말이다. *(위키의 연결)*

- **순수 함수 ≈ 결정적 변환** — 같은 입력 파티션에 다시 돌리면 같은 출력이 나와야 재실행·백필이 안전하다. 단 결정성만으로는 부족하다. 싱크가 덮어쓰기·upsert로 멱등해야 재실행이 결과를 두 벌 쌓지 않는다 → [[멱등성]]. ⚠️ 위키 정정(2026-09-26 린트): 처음엔 "순수 함수 ≈ 멱등한 변환"이라 적었다.
- **불변성 ≈ 덮어쓰지 않는 저장** — 원본을 고치지 않고 새 파티션·새 버전을 쓰는 방식이 재현성과 롤백을 준다.
- **일급 함수 ≈ 변환을 값으로 넘기기** — [[Apache Spark]]에 `map(f)`로 함수를 넘기면 엔진이 그 함수를 여러 노드에 뿌려 실행한다. 함수가 순수해야 어느 노드에서 몇 번 돌려도 결과가 같다.

## Java에서의 한계

Java는 함수형 스타일을 **지원**하지만 **강제**하지 않는다. 람다가 캡처하는 지역 변수는 effectively final이어야 하지만, 필드나 외부 객체의 상태는 람다 안에서 바꿀 수 있다. 불변 컬렉션(`List.of`)·`record`처럼 도구는 있어도, 순수성은 작성자가 지키는 규율이다. 이 점을 무시한 자료의 서술("람다와 스트림은 순수 함수 기반이라 안전")과 그 정정은 [[람다와 스트림]]에 있다.

## 면접에서

- 세 기둥(순수 함수 · 불변성 · 일급 함수)을 모두 말해야 Gold다. 자료는 순수 함수만 말한 답을 Silver로 본다.
- 왜 좋은가까지 잇는다 — 부수 효과가 없으면 **테스트가 쉽고, 순서를 바꾸거나 병렬로 돌려도 결과가 같다**. 이것이 스트림의 병렬화와 지연 연산을 가능하게 하는 전제다. *(위키의 보충)* → [[람다와 스트림]]
- "Java는 순수성을 강제하지 않는다"를 먼저 말해 두면, "그럼 람다는 항상 안전한가?" 같은 꼬리 질문을 미리 막는다.
