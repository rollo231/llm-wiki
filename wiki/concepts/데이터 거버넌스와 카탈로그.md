# 데이터 거버넌스와 카탈로그

- 데이터 거버넌스: 데이터를 조직이 믿고 쓸 수 있도록 표준·권한·가시성을 관리하는 체계.
- 데이터 카탈로그: 그 가시성의 도구. "사내 데이터를 위한 구글 검색이자 도서관 색인 카드."

## 수비에서 공격으로

[[AI DE 강의 1-15 데이터 거버넌스와 카탈로그]]의 전환:

| | 수비형(과거) | 공격형(현재) |
|---|---|---|
| 목표 | 법적 리스크 회피 | AI·분석가가 즉시 찾아 씀 |
| 비유 | 자물쇠 | 나침반 |
| 핵심어 | 보안, 접근 통제, 규제 준수 | 쉬운 발견, 빠른 활용, 신뢰성 |

거버넌스가 없는 레이크는 데이터 늪이 된다. 위치·소유자를 모르고, 정의가 모호하고, 품질을 믿을 수 없다([[데이터 레이크하우스]]).

## 3대 요소

| 요소 | 수단 |
|---|---|
| 표준화 | 전사 데이터 사전, 명명 규칙, 지표 정의 일원화 |
| 권한 관리 | 역할 기반 접근 제어(RBAC), 민감 정보 마스킹, 셀프서비스 승인 워크플로우 |
| 가시성 | 데이터 카탈로그, 계보 시각화, 품질 점수 |

## 3대 메타데이터

| 종류 | 무엇 | 예 | 누가 채우나 (위키의 정리) |
|---|---|---|---|
| 기술적 | 물리적 뼈대 | 테이블 이름·스키마·파티션 | 크롤러가 자동으로 |
| 비즈니스 | 의미와 책임 | 용어 사전, 소유자, PII 여부·보안 등급 | 사람(자동 태깅 + 검수) |
| 운영 | 건강 상태 | 최신성, 품질 점수(Null 비율), 사용량 | 파이프라인·감시 시스템이 |

운영 메타데이터는 [[데이터 SLA]]·[[데이터 관측성]]이 만들어 내는 결과다. 카탈로그는 그 결과를 사용자에게 보여 준다. 이 연결은 위키가 붙였다.

## 데이터 계보

데이터의 탄생부터 모델 소비까지의 흐름. 쓰임새는 세 가지다.

| 쓰임새 | 질문 | 이어지는 곳 |
|---|---|---|
| 원인 역추적 | "모델이 이상하다 — 어제 원본 스키마가 바뀌었나?" | [[데이터 관측성]] |
| 사전 영향도 분석 | "이 테이블을 고치면 누가 다치나?" | [[스키마 진화]] |
| 학습 데이터 증명 | "이 모델은 어떤 데이터를 학습했나?" | [[데이터와 모델 버전 관리]] |

Part 2는 계보를 ML 파이프라인 안으로 가져온다.

- [[AI DE 강의 2-04 ML 데이터 파이프라인]]은 계보를 "운영을 위한 메타데이터"로 둔다. 출처, 변환 단계(누가·언제·무엇을), 사용된 데이터셋 버전. 목적은 장애·품질 이슈의 원인 추적이다.
- [[AI DE 강의 2-10 Feature Store 기본 개념]]이 드는 피처 관리의 실패("변경 이력을 추적할 수 없어 어떤 모델이 어떤 피처를 쓰는지 모른다")는 피처 단위의 계보가 없어서 생긴다([[피처 스토어]]). 이 연결은 위키가 붙였다.

Part 3는 계보를 그래프로 본다.

- [[AI DE 강의 3-06 그래프의 실무 활용]]은 lineage를 그래프의 강점이 가장 직설적으로 드러나는 use case로 꼽는다. lineage는 본질적으로 경로 정보(source → transformation → model → dashboard)이고, 그래프로 모델링할 때 비로소 정적 문서가 아니라 탐색 가능한 운영 도구가 된다고 한다.
- 카탈로그의 질문("이 테이블은 어디서 생성되나", "어떤 대시보드가 쓰나", "누가 책임지나", "바꾸면 어디까지 영향이 가나")은 정답이 한 문서에 없고 자산 사이의 관계를 따라가야 나온다. 그래서 자산을 노드로, upstream·owns·uses를 관계로 둔 메타데이터 그래프를 제안한다([[지식 그래프]]).
- [[AI DE 강의 3-04 그래프의 기본 개념]]은 그 대표 예로 DataHub를 든다. DataHub는 실제로 메타데이터를 그래프로 모델링한다("An entity is the primary node in the metadata graph"). [https://docs.datahub.com/docs/metadata-modeling/metadata-model , 2026-09-28 확인]
- 위의 쓰임새 표 셋 가운데 원인 역추적과 사전 영향도 분석은 둘 다 n-hop 탐색(upstream으로, downstream으로)이다. Part 1이 "계보 시각화"로 부른 것을 Part 3는 질의 가능한 그래프로 바꿔 놓은 셈이다. 이 해석은 위키의 것이고, 강의는 Part 1([[AI DE 강의 1-15 데이터 거버넌스와 카탈로그]])을 참조하지 않는다.

## 권한 관리가 검색 계층으로 옮겨 간다

[[AI DE 강의 2-03 LLMOps]]의 첫 보안 대응은 권한 기반 retrieval이다. 사용자 권한에 따라 검색 대상 문서를 제한한다. 검색 결과에 비밀이 섞이면 모델이 그대로 말해 버리므로 모델보다 앞의 retrieval 계층에서 막아야 한다. 위의 3대 요소 중 "권한 관리"(RBAC·마스킹)가 RAG에서는 벡터 DB 조회 필터로 구현되어야 한다는 뜻이다([[LLMOps]]). 이 연결은 위키가 붙였다.

## 카탈로그는 왜 실패하나 — 그리고 처방

사람이 채우는 카탈로그는 반드시 실제와 어긋난다. 테이블은 매일 수백 개씩 바뀌고, 담당자는 퇴사하고, 한 번 틀린 설명에 속은 사용자는 돌아오지 않는다("예쁜 쓰레기").

처방은 짝을 이룬다:

- 자동 수집: 스키마 크롤링, 쿼리 로그 분석, SQL 파싱으로 자동 계보. LLM 자동 태깅(컬럼명·패턴·샘플 값으로 의미와 PII 판단)과 자연어 검색(Text-to-SQL).
- 배포 게이트: 신규 테이블은 설명 3줄 이상, 오너·도메인 명시, 보안 등급·분류 태그가 없으면 CI/CD에서 배포를 막는다. 사람만 줄 수 있는 메타데이터를 강제하는 장치다.
- 문화: 도메인별 데이터 스튜어드, 주간 태그 리뷰, 온보딩 교육.

운영 목표 예: 메타데이터 최신성 24시간 이내, 변경 감지 알림 100% 커버리지.

## 도구

DataHub · Amundsen · Atlan. DataHub는 Part 3에서 메타데이터 그래프의 예로 다시 나온다([[AI DE 강의 3-04 그래프의 기본 개념]]).

## 목표 — 데이터 민주화

마케터·기획자·분석가 누구나 스스로, 안전하게 데이터를 찾아 쓰는 상태. "안전하게"를 맡는 것이 권한 관리와 PII 태깅이다. [[ETL과 ELT]]의 ELT가 원본(민감 정보 포함)을 레이크에 그대로 쌓는다는 점에서, 이 태깅의 필요가 커진다. 이 연결은 위키가 붙였다.

## 주의

- ⚠️ "데이터 과학자 시간의 80% 낭비"는 출처가 없고, 흔히 인용되는 설문(CrowdFlower 2016)의 내용과도 다르다([[AI DE 강의 1-15 데이터 거버넌스와 카탈로그]]).
- LLM 자동 태깅이 PII를 놓치는 경우의 비용(보안 사고)과 대응은 "담당자 검수" 한 줄뿐이다.
