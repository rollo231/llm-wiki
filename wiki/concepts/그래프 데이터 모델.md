# 그래프 데이터 모델

개체를 노드로, 개체 사이의 연결을 관계(엣지)로 두고 관계 자체를 1급 데이터로 저장하는 데이터 모델이다. [[AI DE 강의 3-04 그래프의 기본 개념]]은 이를 "무엇이 있는가"에서 "무엇과 어떻게 연결되는가"로 옮기는 관점이라고 설명한다. 표현 방식은 크게 Property Graph와 RDF 둘로 갈린다([[AI DE 강의 3-05 Property Graph와 RDF]]).

## 구성 요소와 읽는 단위

| 요소 | 뜻 | 예 |
|---|---|---|
| Node | 개체 | User, Dataset, Dashboard, 모델 버전 |
| Edge (Relationship) | 두 개체 사이의 연결 | DEPENDS_ON, OWNED_BY, PURCHASED |
| Property | 노드·관계에 붙는 key-value | created_at, click_count, confidence |
| Label / Type | 노드·관계의 종류 | `:User`, `:Product` / CLICKED |

그래프를 읽는 단위는 Path(노드와 관계가 이어진 경로), Hop(한 노드에서 다음 노드로 가는 한 단계), Pattern(찾고 싶은 연결 구조 자체)이다. 질문이 "몇 hop을 따라가는가"로 바뀌면 그래프가 자연스러워진다([[AI DE 강의 3-06 그래프의 실무 활용]]).

## 그래프의 종류

- 방향: Directed(lineage, dependency, ownership처럼 실무 관계는 대부분 방향이 있다), Undirected(공동저자, 공동구매).
- 가중치: Weighted(클릭 횟수, similarity score).
- 타입 수: Homogeneous(노드·관계 종류가 하나씩)와 Heterogeneous(여러 종류). 현실 서비스 데이터와 [[지식 그래프]]는 대부분 heterogeneous다.

## Property Graph와 RDF

| | Property Graph | RDF |
|---|---|---|
| 기본 단위 | node · relationship · property | triple (subject · predicate · object) |
| 식별 | 저장소 안의 노드 ID | URI. 출처가 달라도 같은 URI면 같은 자원이다 |
| 관계의 속성 | 관계에 직접 붙인다 | 트리플에 직접 붙일 수 없다. reification이나 RDF 1.2의 triple term이 필요하다 |
| 스키마 | schema-flexible. 제품마다 제약·인덱스를 제공한다 | RDFS·OWL로 어휘와 추론 규칙을, [[SHACL]]로 검증 규칙을 정의한다 |
| 표준 | 질의 언어 GQL(ISO/IEC 39075:2024) | W3C RDF·RDFS·OWL·SPARQL·SHACL |
| 질의 | Cypher·openCypher·Gremlin·GQL | SPARQL |
| 잘 맞는 문제 | 경로 탐색, 추천, fraud, lineage, 영향도 분석 | 이질적 출처의 의미 통합, 추론, 표준 vocabulary 공유(의료·학술·공공데이터) |

표의 식별·관계의 속성·표준 행은 강의에 없고 위키가 보탠 것이다.

강의의 판단 질문 여섯(3-05 p35)은 두 축으로 줄어든다. 경로를 따라가는 탐색이 핵심이면 Property Graph, 여러 출처의 의미를 맞추고 추론해야 하면 RDF다. 이 요약은 위키의 것이다. RDF 쪽의 의미 규칙은 [[온톨로지]]에, Property Graph를 저장·질의하는 엔진은 [[그래프 데이터베이스]]에 있다.

⚠️ 강의는 RDF 스키마를 "RDFS·OWL로 제약조건을 엄격하게 정의"한다고 설명하지만(3-05 p31), RDFS의 domain·range는 위반을 막지 않고 타입을 추론한다. 검증은 SHACL의 몫이다([[온톨로지]]).

## 질의 언어

| 언어 | 모델 | 방식 |
|---|---|---|
| Cypher / openCypher | Property Graph | 선언형. `(a)-[:DEPENDS_ON]->(b)`처럼 패턴을 그림으로 쓴다. Neo4j가 만들었고 openCypher는 그 공개 명세다 |
| Gremlin | Property Graph | Apache TinkerPop의 traversal 언어. 한 step씩 그래프를 따라간다(명령형·선언형·혼합 모두 가능) |
| GQL | Property Graph | ISO 표준 질의 언어(2024) |
| SPARQL | RDF | triple pattern을 조합하는 W3C 표준 |

- GQL은 2024년 4월 ISO/IEC 39075:2024로 발행됐다. [http://peter.eisentraut.org/blog/2024/04/17/gql-2024-is-out , 2026-09-28 확인. ISO 페이지는 열리지 않았다] Neo4j는 GQL을 별도 언어로 두지 않고 Cypher를 GQL 쪽으로 맞춘다. Cypher 매뉴얼의 문구는 "Cypher now accommodates most mandatory GQL features and a substantial portion of its optional ones"다. [https://neo4j.com/docs/cypher-manual/current/appendix/gql-conformance/ , 2026-09-28 확인]
- openCypher 사이트는 "openCypher is an open source specification of Cypher"이고 "Cypher was developed by Neo4j"라고 쓰며, GQL 발행 뒤로는 openCypher 명세를 GQL 적합성 쪽으로 옮겨 간다고 밝힌다. 같은 사이트는 GQL 발행일을 2024-04-11로 적는다. [https://opencypher.org/ , 2026-09-28 확인]
- RDF 쪽 표준은 2026-09 현재 1.2로 개정 중이다. RDF 1.2 Concepts는 Candidate Recommendation(2026-04-07), SPARQL 1.2 Query는 Working Draft(2026-09-21)이고, 현행 권고안은 여전히 RDF 1.1(2014)·SPARQL 1.1(2013)이다. RDF 1.2 Concepts는 "RDF 1.2 introduces the ability to use an RDF triple as a triple term, in the object position of another triple"이라고 적는다. 위 표의 triple term은 이것이고, 목적어 자리에만 올 수 있다. [https://www.w3.org/TR/rdf12-concepts/ · https://www.w3.org/TR/sparql12-query/ , 2026-09-28 확인]
- 강의는 Ch2에서 Cypher와 SPARQL만 비교하고, Gremlin·GQL은 Ch5([[AI DE 강의 3-14 그래프 DB의 특징]])에서 이름만 든다.

## Turtle

RDF 트리플을 텍스트로 적는 문법이다. `a`는 `rdf:type`의 축약, `@prefix`는 접두사 선언, `;`는 같은 주어 반복, `,`는 같은 술어의 목적어 나열, `.`은 문장 끝이다. Part 3에서는 SHACL 예시([[AI DE 강의 3-11 SHACL 검증]])에서 쓰인다.
