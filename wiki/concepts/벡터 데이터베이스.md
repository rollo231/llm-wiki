# 벡터 데이터베이스

[[임베딩]] 벡터를 저장하고, 질의 벡터와 가까운 벡터를 빠르게 찾아 주는 시스템이다([[AI DE 강의 5-02 임베딩과 벡터 검색]] p8). 키워드가 같은 문서가 아니라 뜻이 가까운 문서를 찾게 해 준다. [[검색 증강 생성]]의 검색 단계가 주로 여기에 기댄다.

## 벡터 검색의 다섯 단계

강의 p9의 흐름이다.

| 단계 | 하는 일 | 강의가 드는 세부 |
|---|---|---|
| 1. 문서 임베딩 생성 | 문서를 벡터로 바꾼다 | 문서 분할·청킹, 임베딩 모델 적용 |
| 2. 벡터 인덱싱 | 검색용 인덱스를 만든다 | IVF·HNSW, 클러스터링 |
| 3. 질의 임베딩 | 검색어를 같은 모델로 벡터화 | 쿼리 전처리 |
| 4. 근접 이웃 검색 | 유사도로 가까운 문서를 찾는다 | Top-K 후보 추출, 유사도 계산 |
| 5. 재랭킹·후처리 | 결과를 정제하고 순위를 다시 매긴다 | 결과 필터링 |

1~2는 미리 해 두는 인덱싱이고 3~5는 질의마다 도는 경로다. [[AI DE 강의 5-03 LLM의 한계와 RAG]] p13의 RAG 다섯 단계도 같은 흐름에 생성 단계를 붙인 것이다. 5단계의 재랭킹은 [[리랭킹]]에서 따로 다룬다.

## 근사 최근접 이웃

문서 N개와 질의를 전부 비교하면 비용이 N에 비례한다. 수백만 개가 넘으면 정확한 최근접 대신 근사 최근접 이웃(ANN) 인덱스를 써서, 약간의 누락을 감수하고 비교 횟수를 줄인다. 강의는 IVF와 HNSW를 이름만 들고 동작은 설명하지 않는다. 아래 한 줄 설명은 위키가 붙였다.

- IVF(inverted file): 벡터를 클러스터로 나누고, 질의와 가까운 몇 개 클러스터 안에서만 찾는다. p9의 "클러스터링 적용"이 이것이다.
- HNSW(hierarchical navigable small world): 벡터를 여러 층의 근접 그래프로 잇고, 위층에서 크게 이동한 뒤 아래층에서 좁혀 간다.

어느 쪽이든 recall과 속도·메모리 사이의 맞교환이다. Part 1의 부품표도 근사 최근접 검색 인덱스를 "정확도와 속도의 균형"으로 설명한다([[비정형 데이터 파이프라인]]).

## 제품과 라이브러리

강의 p8은 네 가지를 모두 벡터 DB로 든다. 하나는 라이브러리다.

| 이름 | 성격 | 출처 |
|---|---|---|
| Milvus | 오픈소스(Apache 2.0) 벡터 DB. "a high-performance, cloud-native vector database built for scalable vector ANN search" | https://github.com/milvus-io/milvus |
| Weaviate | 오픈소스(BSD-3) 벡터 DB. "an open-source vector database that stores both objects and vectors" | https://github.com/weaviate/weaviate |
| Pinecone | 관리형 서비스. "the vector database for AI agents and applications" | https://docs.pinecone.io/guides/get-started/overview |
| FAISS | Meta(당시 Facebook AI Research)의 라이브러리. "a library for efficient similarity search and clustering of dense vectors" | https://github.com/facebookresearch/faiss |

[모두 2026-09-28 확인] Pinecone이 오픈소스가 아니라는 점은 인용한 문장에 적혀 있지 않고, 일반적으로 알려진 사실로 붙였다. FAISS는 인덱스와 검색 알고리즘을 주지만, 저장·갱신·메타데이터 필터링·복제 같은 DB 기능은 그 위에 따로 만들어야 한다.

## 벡터 검색만으로는 부족한 곳

벡터 검색은 뜻이 가까운 문서를 찾는 데 강하지만, 제품 코드·버전 번호·고유명사처럼 글자가 정확히 맞아야 하는 질의에서 약하다. 덱 `03`은 이 한계에서 출발해 BM25와 벡터 검색을 합치는 [[하이브리드 검색]]으로 넘어간다([[AI DE 강의 5-04 하이브리드 검색과 리랭킹]]).

## 빈칸

- 강의에는 메타데이터 필터링(권한·날짜로 좁히기)과 벡터 검색을 함께 쓰는 방법이 없다. [[LLMOps]]의 권한 기반 retrieval이 이 기능에 기댄다.
- 인덱스 갱신(문서 추가·삭제, 임베딩 모델 교체 시 재색인)의 운영도 없다([[임베딩]]).
- 전용 벡터 DB와 기존 DB의 벡터 확장(PostgreSQL pgvector, Elasticsearch·OpenSearch의 벡터 필드) 사이의 선택도 다루지 않는다. 위키가 적어 둔 빈칸이다.
