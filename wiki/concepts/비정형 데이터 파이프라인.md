# 비정형 데이터 파이프라인

PDF·이미지·영상·로그·SNS 게시글처럼 **스키마가 없는 데이터를 모아, AI가 계산할 수 있는 텍스트와 벡터로 바꾸는
파이프라인.** [[AI DE 강의 1-01 기존 DE와 AI DE]]가 AI DE와 기존 DE를 가르는 세 역할 중 하나로 든다.

## 정형과 비정형

| | 정형 | 비정형 |
|---|---|---|
| 스키마 | 행·열이 고정 | 없음 |
| 저장 | RDBMS | 오브젝트 스토리지, NoSQL, 데이터 레이크 |
| 처리 | SQL | AI 모델, OCR, 자연어 처리 |
| 무엇을 알려 주나 | **결과** — "평점이 1.0이다" | **원인** — "옷감이 거칠고 피부가 따갑다" |

## 4단계

[[AI DE 강의 1-09 비정형 데이터 수집과 전처리]]가 "구구단처럼 외우라"는 골격이다.

| 단계 | 하는 일 | 설계 포인트 |
|---|---|---|
| 1. 수집 | 웹 크롤러, 공식 API, 실시간 스트리밍 | 상대 서버를 배려하는 수집과 호출량 제한, 재시도, **중복 수집 방지(멱등성)** |
| 2. 저장 | 원본 파일은 오브젝트 스토리지, 속성 정보(경로·생성일·출처·작성자·태그)는 NoSQL | **이원화**, 날짜 기반 파티셔닝, 수명주기로 아카이브 이동 |
| 3. 처리 | 텍스트 추출(OCR·STT) → 정제(정규표현식·불용어) → PII 비식별화 → 임베딩 → 벡터 DB | 대용량은 분산 처리, 실패 데이터 격리·재처리 |
| 4. 활용 | RAG 챗봇, BI(감성 분석·토픽 트렌드), API | 캐싱, 호출량 제한 |

### 저장 이원화

"무거운 몸체(데이터)는 S3에, 가벼운 영혼(정보)은 DB에." 저장 비용은 싸게, 검색은 빠르게 유지한다.
원본과 그것을 찾게 해 주는 설명을 분리하는 원리는 [[데이터 레이크하우스]](데이터 파일 + 트랜잭션 로그)와
[[데이터 거버넌스와 카탈로그]](데이터 + 메타데이터)에서도 같다. *(위키의 연결)*

### 처리는 ETL의 Transform이다

정형 ETL의 정제·PII 마스킹이 그대로 있고, 그 앞뒤에 OCR과 임베딩이 붙는다. → [[ETL과 ELT]]

## 검색 쪽 부품

| 부품 | 역할 | 예(덱) |
|---|---|---|
| 임베딩 모델 | 텍스트를 고차원 벡터로. 뜻이 비슷하면 가깝다 | BERT, E5 등 — 데이터와 언어(한국어)에 맞는 모델을 고른다 |
| 벡터 DB | 벡터 간 거리 계산, 수억 개 저장 | Milvus, Pinecone, Weaviate |
| 근사 최근접 검색 인덱스 | 정확도와 속도의 균형 | HNSW, IVF |
| 리랭킹 | 1차 결과를 질문과 함께 다시 채점 | Cross-Encoder |

**RAG**는 LLM의 한계(학습 시점 이후 정보 부재, 사내 문서 접근 불가, 환각)를 사내 문서를 먼저 검색해 근거로
답하게 해서 보완한다. "암기 테스트가 아니라 오픈북 테스트."

### RAG 운영

Part 2는 RAG를 **운영 대상**으로 다시 본다. [[AI DE 강의 2-01 데이터 파이프라인의 진화와 데이터 엔지니어]]의 Basic RAG
Pipeline 그림은 인덱싱(문서 → 청크 분할 → 임베딩 → 벡터 DB)과 검색·생성(질의 임베딩 → Top-K 청크 → LLM → 응답) 두
구역으로 나누고, [[AI DE 강의 2-03 LLMOps]]는 청킹 전략·임베딩 모델 버전·벡터 DB 인덱스·retrieval 설정을 버전으로
관리할 변경 지점으로, 권한 기반 retrieval·컨텍스트 정화를 보안 대응으로 든다. → [[LLMOps]]

RAG 자체의 세부(하이브리드 검색·리랭킹)는 Part 5의 전용 강의에서 다룬다 — 아직 인제스트하지 않았다.

## 설계 원칙

- **입력이 제각각이어도 멈추지 않는다** — 1GB 영상부터 깨진 파일까지. 문제 데이터를 격리하고 재처리한다.
- **품질이 지능의 상한이다** — 전처리가 부족하면 모델은 환각을 일으킨다(GIGO).

## 빈칸

- **청킹** — 문서를 어떤 단위로 잘라 임베딩할지가 RAG 품질의 핵심인데 Part 1에 없다. Part 2에도 청킹은 그림의 한
  단계("Data Splitting", 2-01)와 버전으로 관리할 변경 지점(2-03)으로만 나오고 **방법은 여전히 없다.**
- **임베딩 모델을 바꾸면 전체를 다시 임베딩해야 한다** — Part 1은 벡터와 모델의 버전 관리를 다루지 않는다. Part 2의
  [[AI DE 강의 2-03 LLMOps]]가 "Embedding 모델 버전"과 "Vector DB 인덱스·스키마"를 관리 대상으로 들지만, 모델을 바꿀 때
  재임베딩·인덱스 교체를 어떻게 하는지는 설명하지 않는다.
- 멀티모달(이미지·오디오를 직접 임베딩)은 이름만 나온다.
