# 스트림 처리

끝이 정해지지 않은 데이터(unbounded)를 **발생하는 대로** 처리하는 방식. 이벤트가 생기자마자 반응해 데이터가
가장 신선할 때 가치를 만든다.

## 세 가지 난관과 세 가지 장치

[[AI DE 강의 1-12 실시간 처리 엔진]]의 세 난관에 강의가 소개하는 장치를 짝지으면 일대일로 맞물린다. *(위키의 정리)*

| 난관 | 무엇이 어려운가 | 장치 |
|---|---|---|
| 무한성 | 끝이 없으니 "다 모아서" 처리할 수 없다 | **윈도우** — 끝을 만든다 |
| 비동기성 | 생성 순서와 도착 순서가 다르다 | **이벤트 시간과 워터마크** — 순서를 복원한다 |
| 상태 보존 | 멈추면 안 되는데 중간 계산값은 메모리에 있다 | **체크포인트** — 멈춰도 이어 간다 |

## 윈도우

| 종류 | 모양 | 용도 | 주의 |
|---|---|---|---|
| Tumbling | 겹치지 않는 고정 크기 | 분·시간 단위 집계. 가장 저렴 | 경계에 걸친 패턴이 두 윈도우로 쪼개진다 |
| Sliding | 크기 + 이동 간격, 겹친다 | 이동평균, "최근 5분 에러율" 경보 | 한 데이터가 여러 윈도우에 속한다 |
| Session | 활동이 끊기는 간격(gap)으로 구분 | 체류 시간, 이탈 직전 행동 | 크기를 예측할 수 없다 |

## 이벤트 시간과 늦은 데이터

- **이벤트 시간** — 데이터가 실제로 발생한 시각. 사건의 순서를 반영해 정확하다.
- **처리 시간** — 엔진에 도착한 시각. 간단하고 빠르지만 네트워크 지연으로 결과가 왜곡된다.
- **워터마크** — "이 시각까지의 데이터는 다 왔다"는 신호. 늦은 데이터를 얼마나 기다릴지 정한다.

늦게 온 데이터를 어떻게 할지는 정확성·비용·복잡도의 선택이다.

| 전략 | 방식 | 대가 | 사용처 |
|---|---|---|---|
| Drop | 허용 지연을 넘으면 버린다 | 유실 | 실시간 대시보드 |
| Update | 이미 낸 결과를 다시 계산해 갱신 | 싱크가 upsert를 지원해야 | 정산, 리포트 |
| Side Output | 따로 모아 나중에 보정 | 별도 배치 보정 파이프라인 | 로그 아카이빙, 재처리 |

### 시간 기준이 갈리면 스큐가 된다

[[AI DE 강의 2-06 Training-Serving Skew 예방]]은 이 구분을 모델 쪽에서 다시 쓴다. "최근 10분" 피처를 학습은 배치로
**이벤트 시간** 기준으로 쉽게 집계하지만, 서빙은 실시간이라 **처리 시간** 기준이 되기 쉽고, 늦거나 빠진 이벤트 때문에
집계에 들어가는 이벤트 집합 자체가 달라진다. 강의의 처방은 두 시간 중 하나로 **고정해 양쪽에 똑같이 적용**하고, 늦은
이벤트를 워터마크로 얼마나 허용할지 **정책으로** 정하는 것이다. → [[학습-서빙 스큐]]

## 상태와 exactly-once

- **Stateless**(필터·맵·파싱)는 확장이 쉽고, **Stateful**(윈도우·조인·집계)은 과거를 기억해야 한다.
- 상태는 **키별(Keyed)**로 나뉘어 병렬 처리되고, 연산자 단위(Operator) 상태에는 Kafka 오프셋 같은 입력 위치가 들어간다.
- **체크포인트** — 주기적으로 상태를 일관된 스냅샷으로 떠서 HDFS·S3에 저장하고, 장애 시 그 시점부터 재처리한다.
  **상태와 입력 오프셋을 함께** 찍기 때문에, 복구하면 상태를 되돌린 만큼 입력도 되감아 한 번만 반영된다.
  → [[Apache Kafka]]

## 엔진

| | [[Apache Flink]] | [[Apache Spark]] |
|---|---|---|
| 모델 | 네이티브 스트리밍(레코드 단위) | 마이크로 배치(짧은 간격으로 모아 처리) |
| 지연 | 밀리초 | 초 단위(트리거 간격에 따라) |
| 강점 | 초저지연, 이벤트 시간, 세밀한 상태 제어 | 배치와 같은 API, 코드 재사용, 처리량 |
| 운영 | 복잡 | 상대적으로 쉬움 |

마이크로 배치는 [[지연 시간과 처리량]]의 절충점이다 — 0.5초~수 초를 모아 1~5초 지연에 배치에 가까운 효율을 낸다.

## 언제 스트리밍을 쓰나

[[AI DE 강의 1-10 배치 vs 스트리밍]]: 데이터 가치가 초 단위로 사라지고(이상 거래 탐지·실시간 추천·경보), 24x7
운영 역량이 있을 때. 나머지는 [[배치 처리]]가 기본이다. 스트리밍의 대가는 건별 오버헤드, 순서·유실 대응, 상태 관리의
복잡성이다.
