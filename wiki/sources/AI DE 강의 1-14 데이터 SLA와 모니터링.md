## 요약

### (1) 침묵의 실패와 데이터 SLA

- **침묵의 실패** — 전통 IT SLA는 서버 가동률(99.9%)을 약속한다. 그러나 파이프라인이 exit code 0으로 끝나고
  에러 로그도 없고 스케줄러가 초록불인데, **결과 테이블은 0건**(예상 100만 건)이고 결제 금액은 Null·음수일
  수 있다. 기존 IT 모니터링으로는 잡을 수 없다.
- **데이터 SLA** — 데이터 생산자(엔지니어)와 소비자(AI 모델·데이터 사이언티스트) 사이의 계약. 예시 명세:
  적시성(매일 08:00까지 적재), 완전성(소스 대비 100%), 정확성(결제 금액 Null·음수 0건), 위반 시 즉시
  알람·롤백. 운영 절차는 실시간 모니터링 → 위반 감지·알림 → 모델 학습 중단·에스컬레이션.
- **나비효과** — VIP 구매 데이터 수집 실패 → 잘못된 데이터로 재학습 → 엉뚱한 상품 추천 → VIP 이탈 →
  매출 손실. "알고리즘은 죄가 없다."

### (2) 세 가지 지표

| 지표 | 질문 | 측정 | 대응 |
|---|---|---|---|
| 신선도 | 약속한 시간에 도착했는가? | `Latency = Now() - Event_Timestamp`, 평균보다 p95·p99 꼬리 | 배치: D-1 로그 08:00 목표, 08:10 도착은 위반, 08:30 초과 시 호출 / 스트리밍: 클릭 후 3초 내 반영, p95 기준 |
| 완전성 | 기대한 데이터가 100% 왔는가? | 소스·타깃 건수 비교와 해시 비교(대사), PK 중복 검사 | 금융·결제는 오차 0 허용, 누락 탐지 시 백필 자동 트리거(MTTR 30분 목표) |
| 정확성·유효성 | 형태와 값이 규칙을 만족하는가? | 스키마(컬럼 수), 타입, 도메인 규칙(email에 `@`), 범위(0 < age < 120), 통과율 99.9% 목표 | 실패 레코드 격리 → 담당자 알림 → 자동 정정·재처리 |

- 누락은 특정 시간대·사용자군이 통째로 빠지는 **편향**으로 이어진다.
- 체크리스트: 모든 주요 파이프라인에 데드라인 명문화, 소스·타깃 건수 자동 대사, 배포 전 스키마·도메인
  규칙 테스트를 CI/CD에 포함.

### (3) 관측·알림·차단

- **데이터 관측성** — 사람이 수천 개 파이프라인을 매일 확인할 수는 없다. 볼륨·신선도·스키마 변경·값 분포를
  시스템이 자동 수집하고, 과거 정상 패턴을 학습한 이상 탐지로 먼저 잡는다.
- **경고 피로 방지** — 비즈니스에 타격을 주는 핵심 SLA 위반만 울린다. 고정값 대신 시간대·계절성을 반영한
  동적 임계치. 경미한 이슈는 대시보드로, 심각한 장애만 온콜로.
- **장애 대응** — 감지 → 격리 → 완화 → 원인 규명 → 복구. 소비 팀에 "인지 중, 복구 예정"을 즉시 알린다.
  근본 원인 분석(RCA) 뒤 재발 방지 대책(CAPA).
- **서킷 브레이커** — "멈춤이 최선의 품질". 데이터가 이동하는 단계 사이에 게이트를 두고, 규칙을 위반하면
  (예: Null 비율 1% → 50%) 하류 전파를 막고 안전 모드로 전환한다(예: 어제 데이터 사용).
- 결론: **"SLA는 종이 위의 약속이 아니다. 시스템으로 지켜질 때 비로소 진짜 약속이 된다."**

## 핵심

- 이 강의의 중심은 **"에러 없는 실패"**다. [[학습-서빙 스큐]]도 에러 로그를 남기지 않았다 — 운영 파트 전체가
  "시스템은 건강한데 데이터가 아프다"를 어떻게 잡을지에 관한 이야기다. → [[데이터 SLA]]
- 세 지표를 "측정 → 대응"까지 짝지어 준다는 점이 실무적이다. 특히 **서킷 브레이커의 fail-safe(어제 데이터
  사용)**는 "틀린 최신 데이터보다 맞는 어제 데이터"라는 판단을 명시한다. → [[데이터 관측성]]

## 주의·결함

- **같은 파트 안에서 데이터 품질의 축이 세 가지 버전으로 나온다.** 이 강의는 3대 지표(신선도·완전성·정확성),
  [[AI DE 강의 1-13 Skew와 Drift]]는 데이터 SLA 4대 축(신선도·분포 안정성·품질/완전성·피처 일관성),
  [[AI DE 강의 1-16 AI 파이프라인 구축 사례]]는 5대 기둥(정확성·완전성·일관성·신선도·공정성). 서로를 참조하지
  않는다. → [[데이터 SLA]]에서 대조했다.
- 관측성 도구는 이름이 하나도 나오지 않는다. "ML 기반 이상 탐지"도 방법이 설명되지 않는다.
- MTTR 30분, 통과율 99.9%, 08:00 데드라인 등은 **예시 목표값**이다.
