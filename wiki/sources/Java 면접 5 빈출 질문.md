# Java 면접 5 빈출 질문

[[인프런 Java 면접 강의]] Section 5(객체지향 프로그래밍)의 부록 PDF다. 부록이라는 것은 제목의 "[객체지향 프로그래밍]"이 Section 5 제목과 같아서 한 추론이다. [[Java 면접 4 빈출 질문]] 등 앞의 부록과 형식이 같다. 질문은 19개이고, 질문마다 빈도 별점(⭐1~3)과 짧은 답 하나가 붙는다. 등급 루브릭은 없다. 슬라이드 쪽 [[Java 면접 5 객체지향 프로그래밍]]은 캡슐화·상속·다형성·인터페이스를 다루고, 이 자료는 그 밖의 주제인 객체와 클래스, 역할·책임·협력·메시지, 절차지향과의 차이, 결합도와 응집도, SOLID, static, 클린 코드, 관심사 분리를 다룬다.

## 핵심

- Q2~Q6의 어휘(역할·책임·협력·메시지, 「자율적인 객체」)는 조영호 『오브젝트』(2019)의 정의와 거의 같다. 자료는 출처를 밝히지 않는다. 대조는 2차 자료로 했다([[객체지향 프로그래밍]]).
- 별점 셋짜리 여섯 질문(Q2 · Q7 · Q8 · Q13 · Q14 · Q15) 가운데 Q8 · Q13 · Q14에 틀린 서술이 있다. 가장 자주 나온다는 질문에서 정의가 흔들리므로 그대로 외우면 위험하다.
- Q7 · Q10은 결합도·응집도·변경 용이성을 모두 캡슐화 하나로 푼다. 캡슐화가 결합도를 낮추는 것은 맞지만, 응집도는 무엇을 한 객체에 모으느냐의 문제라 캡슐화만으로 올라가지 않는다. 이 지적은 위키의 것이다([[결합도와 응집도]]).
- Q12의 SRP와 Q17~Q19는 한 흐름이다. 「책임 = 변경 이유 = 액터」라는 Martin의 『Clean Architecture』 정의를 자료가 출처 없이 옮기고, 사례로 이어 간다([[SOLID 원칙]]).
- Q19의 사례(PG사별 분기를 인터페이스 뒤로)는 [[다형성]]의 OCP 예, [[상속을 쓰는 이유]]의 인터페이스 + 조합과 같은 구조다. 이 연결은 위키가 했다.

## 주의·결함

외부 검증 결과다(2026-09-27). 대조한 1차 자료: JLS SE 25 §4.3.1 · §8.4.3.2 · §8.4.8.1–2 · §9.8 · §15.12.4.1 · §15.27.4, Martin 「Design Principles and Design Patterns」(2000) · 「The Dependency Inversion Principle」(1996) · 「The Interface Segregation Principle」(1996), Liskov 「Data Abstraction and Hierarchy」(1987), Oracle Java Tutorial 「What Is an Object?」, Fowler 『Refactoring』 2판 1장. 조영호 『오브젝트』 · Martin 『Clean Architecture』 · 『Clean Code』 · Bloch 『Effective Java』는 2차 자료로 표시했다.
