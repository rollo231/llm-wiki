## LLM 작동 원리 5단계 (중복 슬라이드)

첫째 덱과 겹치지만 **한 가지가 여기에만 있다 — 디코딩 단계**:

```
1. 대규모 사전학습  2. 토큰화  3. 어텐션 메커니즘  4. 확률 예측  5. 출력 생성
                                              Softmax 확률 계산   텍스트 디코딩
                                              Top-k 샘플링       결과 정제
```

**Top-k 샘플링**이 코스에서 처음이자 유일하게 언급되는 지점이다(설명은 이 한 단어가 전부).
temperature·top-p 등 다른 디코딩 파라미터는 없다.

## 임베딩이란

> **"고차원의 정보(텍스트, 이미지 등)를 저차원의 숫자 벡터로 표현하는 기술.
> 비슷한 의미를 가진 단어들은 비슷한 벡터로 표현되어, 컴퓨터가 의미를 이해할 수 있게 한다."**

```
"강아지" = [0.8, 0.6]        "고양이" = [0.7, 0.5]

강아지 ↔ 고양이   유사도 0.85
강아지 ↔ 자동차   유사도 0.15
```

임베딩이 여는 것 넷: **유사도 검색 및 매칭**(키워드 매칭의 한계 극복) · **AI 성능 향상**(추천·
클러스터링) · **문맥 파악 개선**(동음이의어·다의어 구분) · **멀티모달 연결**(CLIP 등 텍스트-이미지).

## ⭐ 임베딩 알고리즘 비교

**이 덱에서 가장 쓸모 있는 슬라이드.** 축은 `맥락 반영` 하나다.

| 알고리즘 | 맥락 반영 | 특징 |
|---|---|---|
| **Word2Vec** | **정적 벡터** | 주변 단어 예측. 빠르고 가벼움. 단어 임베딩 |
| **GloVe** | **정적 벡터** | 전역 동시 등장 통계. 선형 관계 표현, 아날로지 강점 |
| **FastText** | **정적 벡터** | **서브워드 단위** 학습 → 희귀어/신조어 처리 우수. Word2Vec 확장 |
| **BERT** | **문맥 반영** | 트랜스포머 기반 양방향 언어 모델. **동적 임베딩** |
| **SBERT** | **문맥 반영** | **문장 임베딩 특화.** 의미 유사도 강함. BERT 기반 |
| **CLIP** | **멀티모달** | 이미지-텍스트 공동 임베딩 (OpenAI) |

> ⭐ **정적 벡터 / 문맥 반영의 구분이 실무 판단의 축이다.**
> 정적 벡터는 `"배"`가 문장 어디에 있든 같은 벡터다. 문맥 반영 모델은 문장마다 다른 벡터를 준다.
> **RAG의 문서 임베딩에는 SBERT 계열(문장 임베딩 특화)이 쓰인다** — 이유는 아래 벡터 검색 절과
> [[AI DE Course - Part5 Hybrid search and reranking|덱 3의 Bi-Encoder]]에서 드러난다.

⚠️ **다만 이 표의 "성능 %" 열은 신뢰할 수 없다** — 아래 문제 절 참고.

## 벡터와 벡터 공간

- **차원(Dimension)** — 벡터의 길이, 특징의 수 (예: **384, 768**)
- **유사도** — 코사인 유사도 / 유클리드 거리
- **의미 공간** — 비슷한 의미는 벡터 공간에서 가까운 위치

## 벡터 데이터베이스

> **"임베딩 벡터를 효율적으로 저장하고 빠르게 검색할 수 있도록 도와주는 시스템.
> 의미 기반 검색을 가능하게 하여 전통적인 키워드 검색의 한계를 극복한다."**

셋을 든다: **의미 기반 저장** · **효율적인 검색**(근접 이웃 검색) · **확장성**.

| 제품 | 강의의 설명 (전부 한 줄이다) |
|---|---|
| **Milvus** | 오픈소스 기반 벡터 DB. 빠른 검색 속도와 우수한 확장성 |
| **FAISS** | **Facebook AI 연구팀 개발.** 대량 벡터에 대한 빠른 근접 이웃 검색 |
| **Pinecone** | **클라우드 기반 관리형** 벡터 DB. API로 손쉽게 사용 |
| **Weaviate** | **멀티모달** 데이터 검색에 강점. AI 네이티브 벡터 DB |

> ⚠️ **FAISS는 나머지 셋과 층위가 다르다** — 데이터베이스가 아니라 **인덱싱/검색 라이브러리**다.
> 서버·영속성·메타데이터 필터링·복제가 없다. 강의는 넷을 나란히 놓아 이 차이를 지운다.
> → [[Vector database]]에서 정리했다.

## ⭐ 벡터 검색의 원리 5단계

```
1. 문서 임베딩 생성  2. 벡터 인덱싱   3. 질의 임베딩  4. 근접 이웃 검색  5. 재랭킹/후처리
문서 분할 및 청킹     IVF/HNSW 인덱싱   쿼리 전처리      Top-K 후보 추출    결과 필터링
임베딩 모델 적용      클러스터링 적용     임베딩 생성      유사도 계산        정확도 최적화
```

**IVF / HNSW**가 인덱싱 방식으로 이름만 나온다(원리 설명은 없다).

> ⭐ **5단계의 마지막이 "재랭킹"이라는 점이 중요하다.** 이 덱은 재랭킹을 파이프라인 한 칸으로만
> 두고 넘어가는데, **그 한 칸을 통째로 펼친 것이
> [[AI DE Course - Part5 Hybrid search and reranking|덱 3]]**이다. Part 5 세 덱 중 실질적인 깊이는
> 거기에 있다.

## 기존 위키와의 관계

[[Unstructured data ingestion]](Part 1 CH03-5,6)이 이미 **비정형 파이프라인 4단계의 마지막 칸**으로
임베딩·Vector DB·ANN·재순위화를 다뤘다. 겹치는 부분과 새로 얻은 것:

| | Part 1 (CH03-5,6) | Part 5 (이 덱) |
|---|---|---|
| Vector DB 제품 | Milvus · Pinecone · Weaviate | **+ FAISS** |
| ANN 인덱스 | HNSW · IVF (**"0.1초 내 응답"**) | HNSW · IVF (수치 없음) |
| 임베딩 모델 | **"한국어 최적화 모델 선정이 필수"** ⭐ | 알고리즘 6종 비교표 ⭐ |
| 재순위화 | **Cross-Encoder로 정밀 채점** (한 줄) | 파이프라인 5단계의 마지막 칸 |

**모순은 없다. Part 1이 "무엇을 쓰나"였다면 이 덱은 "무엇 중에 고르나"를 표로 준다.**

## ⚠️ 이 덱의 문제

| 문제 | 내용 |
|---|---|
| ⚠️⚠️ **출처 없는 장식 수치** | 슬라이드마다 배지가 붙는다: `95% 검색 정확도` `10x 속도 향상` `85% 추천 정확도` `+40% 성능 향상` `90% 문맥 정확도` `-30% 오류 감소` `88% 매칭 정확도` `+25% 활용도`. **어떤 태스크·데이터·기준인지가 전무하다.** Part 1의 "80%" 관행보다 더 나쁘다 — 그쪽은 최소한 문장 안에 있었는데 여기는 **숫자만 크게 떠 있다** |
| ⚠️⚠️ **알고리즘 비교표의 성능 열** | Word2Vec 75% · GloVe 80% · FastText 78% · BERT 92% · SBERT 88% · **CLIP 95%**. 각주는 *"성능은 다양한 벤치마크 테스트 결과를 기반으로 함"*이 전부. **어느 벤치마크인지 밝히지 않을 뿐 아니라, 축이 다른 모델을 단일 숫자로 서열화한다** — CLIP(이미지-텍스트 검색)과 Word2Vec(단어 임베딩)은 같은 과제를 풀지 않는다. **표의 나머지 열은 정확하므로 이 열만 버리면 된다** |
| **FAISS 층위 오류** | 라이브러리를 관리형 DB들과 나란히 배치 (위 참고) |
| **중복 슬라이드 2장** | p2·p3이 첫째 덱과 겹친다 |
| **IVF/HNSW가 이름뿐** | 인덱싱 방식의 트레이드오프(정확도 vs 메모리 vs 빌드 시간)가 없다. [[Vector database]]에 채워뒀다 |
| **청킹 전략이 없다** | "문서 분할 및 청킹"이 한 줄. chunk size·overlap의 판단 기준은 RAG 품질의 핵심 변수인데 다루지 않는다 (덱 4에 "오버랩 설정"이 역시 한 줄로 나온다) |
