## 핵심

- 별점이 높은 두 질문(Q1 · Q5)은 정의와 메모리 구조다. 로딩 세부(Q4)는 별 하나다. 여기서 면접관이 구조도를 그릴 수 있는지를 먼저 본다고 읽는 것은 위키의 관찰이다. 별점의 기준은 자료에 없다.
- 답은 모두 JVMS의 "논리 모델" 수준에 머물고 HotSpot 구현은 말하지 않는다. 꼬리 질문은 이 틈으로 오기 쉽다. "메서드 영역은 실제로 어디에 있나"(Metaspace), "static 필드는 어디 있나"(JDK 7부터 힙), "JIT 코드는 어디 있나"(코드 캐시) 같은 질문이다([[JVM 메모리 구조]]).
- 슬라이드 Section 2와 이어진다. 이 자료의 "실행 엔진"은 슬라이드의 인터프리터와 [[JIT 컴파일]]이다. 슬라이드 Q2 실행 과정의 ③ "클래스 로더가 필요한 시점에 로딩"을 이 자료가 풀어 쓴다. 두 자료를 이은 것은 위키다.

## 주의·결함

외부 검증(2026-09-26, JVMS SE 25 §1.2 · 2장 · 5장, JEP 122 · 261, HotSpot Runtime Overview 대조) 결과:

| 질문 | 자료의 서술 | 판정 | 정정이 있는 곳 |
|---|---|---|---|
| Q1 | JVM은 "가상의 운영 체제" | 틀림. JVMS는 "abstract computing machine"이라 부른다 | [[JVM]] |
| Q2 | 클래스 로더 · 런타임 데이터 영역 · 실행 엔진 | 단서 필요. 교과서에서 흔히 쓰는 틀이고 JVMS의 분류가 아니다. "실행 엔진"은 JVMS에 없는 용어다 | [[JVM]] |
| Q3 | 클래스 로더가 로딩 · 링크 · 초기화를 한다 | 틀림. 클래스 로더는 로딩만 맡는다. 링크와 초기화는 JVM이 한다 | [[클래스 로딩]] |
| Q4 | 링크 = 검사 · 메모리 할당 · 참조 교체 | 단서 필요. 검증 · 준비 · 해석 세 단계의 이름이 빠졌다. "준비"는 static 필드를 기본값으로 만드는 단계다. 해석은 lazy할 수 있다(HotSpot은 lazy). 초기화는 `<clinit>`을 실행한다 | [[클래스 로딩]] |
| Q5 | 메모리 구조 "5가지" | 단서 필요. 자료는 런타임 상수 풀을 메서드 영역 안에 넣어 5로 센다. 흔한 셈법이지만 JVMS §2.5는 상수 풀을 따로 두어 6개 절로 나눈다 | [[JVM 메모리 구조]] |
| Q5 | PC 레지스터 = "바이트 코드 몇 번째 줄" | 틀림 (표현). 현재 실행 중인 명령어의 주소다. native 메서드를 실행하는 중에는 값이 정의되지 않는다 | [[JVM 메모리 구조]] |
| Q5 | 스택 프레임 = 지역 변수 배열 · 피연산자 | 단서 필요. 런타임 상수 풀 참조도 프레임에 있다 | [[JVM 메모리 구조]] |
| Q5 | 힙 = 인스턴스 | 단서 필요. 배열도 힙에 있다 | [[JVM 메모리 구조]] |

- 문서 안의 결함: Q5의 "메소드" 항목은 "메소드 영역"에서 "영역"이 빠졌다. Q4의 "심볼릭 메모리 레퍼런스"는 "심볼릭 레퍼런스"가 맞는 용어다.
