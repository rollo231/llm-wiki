# AI DE 강의 3-06 그래프의 실무 활용

## 요약

### 01. 그래프는 언제 써야 하는가

- 그래프는 모든 데이터를 담는 만능 저장소가 아니다. 관계가 핵심이고, 중간 경로와 영향 범위를 알아야 하는 문제에서 강점이 드러난다.
- 적용처 넷: 메타데이터 관리와 데이터 카탈로그, lineage와 영향도 분석, 추천 시스템, 검색과 지식 연결.
- 잘 맞는 문제의 공통점(p39): 엔터티보다 관계가 중요(계정-기기-결제수단), 질문이 1-hop에서 끝나지 않음, 재귀·패턴 탐색이 필요(순환, 공통 연결점, n-hop 이웃), 스키마는 고정돼도 연결 구조가 계속 진화.
- RDB만으로 안 되는 이유(p40): 강의는 "JOIN이 많아지면 그래프"라는 통념을 부정한다. 기준은 JOIN 횟수가 아니라 질문의 의미가 다단계 연결 탐색인가다.

| RDB가 잘하는 질문 | 그래프가 자연스러운 질문 |
|---|---|
| 어제 주문 건수 | 이 지표가 깨졌을 때 어떤 잡과 소스까지 영향이 전파되는가 |
| 카테고리별 매출 합계 | 이 상품을 본 사용자와 유사 행동을 보인 사용자들은 무엇을 샀는가 |
| 상위 10개 상품 | 같은 전화번호·기기·주소를 공유한 계정 묶음은 무엇인가 |

### 02. 메타데이터 관리와 데이터 카탈로그

- 데이터 엔지니어 관점에서 가장 직관적인 활용처다.

| 실무 질문 | 그래프로 관리하면 |
|---|---|
| 이 테이블은 어디서 생성되는가 | 계보 추적 |
| 어떤 대시보드가 이 데이터를 쓰는가 | 영향도 분석 |
| 누가 책임지는가 | 책임자와 문서 연결 |
| 변경 시 어디까지 영향이 가는가 | 검색과 탐색 품질 향상 |

- 메타데이터 그래프가 필요한 이유(p43): "이 대시보드는 어떤 데이터셋을 쓰나요?" 같은 질문의 정답은 한 문서 안에 없고 여러 자산 사이의 관계를 따라가야 나온다. 메타데이터 그래프는 탐색형 질의, 연관 자산 추천, 영향도 분석, 변경 안전성 판단, 지식 축적을 동시에 가능하게 한다.

### 03. Lineage와 영향도 분석

- 강의는 그래프의 강점이 가장 직설적으로 드러나는 use case로 lineage를 꼽는다. lineage는 본질적으로 경로 정보(source → transformation → model → dashboard)다.
- "이 테이블 수정하니까 대시보드 에러나요." lineage는 그래프로 모델링할 때 비로소 정적 문서가 아니라 탐색 가능한 운영 도구가 된다.

### 04. 추천

- 사용자-상품 직접 관계만이 아니라 사용자-상품-카테고리, 사용자-상품-다른 사용자-다른 상품 같은 다단계 연결을 탐색한다.
- cold-start(로그가 적은 사용자, 상호작용이 없는 신규 아이템)에서 행동 이력의 부족을 주변 관계 신호로 보완한다.

### 05. 검색과 Knowledge Graph

- 검색은 문자열 매칭만으로 끝나지 않는다. 찾는 대상이 사람인지 장소인지, 어떤 관계를 갖는지 이해해야 한다.
- 지식 그래프의 역할: 엔터티와 사실 관계 구조화, 의미 기반 검색, 지식 패널 생성, 질문 응답 정확도 향상, 동의어와 표기 변형을 넘어 같은 대상 연결.
- 전통적 검색은 질의어와 일치하는 문자열을 찾는다. 그래프가 결합된 검색은 질의어가 가리키는 엔터티를 파악하고, 연관 엔터티를 탐색하고, 의도와 맥락을 보강해 더 적절한 결과와 설명을 낸다.

## 핵심

- "JOIN 횟수가 아니라 질문의 의미"가 이 소단원에서 가장 쓸모 있는 기준이다. 판단을 테이블 수가 아니라 질문의 모양(n-hop, 재귀, 공통 연결점)으로 옮긴다. 같은 기준이 [[그래프 데이터베이스]]의 RDB·그래프 선택으로 이어진다.
- 메타데이터 그래프와 lineage는 Part 1의 카탈로그·계보를 그래프 관점으로 다시 쓴 것이다. 전문은 [[데이터 거버넌스와 카탈로그]]의 계보 절과 [[지식 그래프]]의 메타데이터 그래프 절에 있다. 강의는 Part 1([[AI DE 강의 1-15 데이터 거버넌스와 카탈로그]])을 참조하지 않는다.
- "정답이 한 문서 안에 없고 관계를 따라가야 나온다"(p43)는 [[AI DE 강의 3-12 RAG의 이해와 한계]]가 드는 RAG의 첫 한계(검색 단위는 chunk, 질문 단위는 structure)와 같은 관찰이다. Ch2와 Ch4는 이 연결을 말하지 않는다. 이 연결은 위키가 붙였다.
