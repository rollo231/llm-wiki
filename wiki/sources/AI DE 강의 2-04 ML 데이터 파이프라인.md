## 요약

### ML 파이프라인은 운영되는 시스템을 만든다

- **BI는 사람이 해석하는 결과를, ML은 모델이 직접 소비하는 입력을 만든다.** 데이터가 곧 성능이고 성능이 곧
  제품 품질이다. 운영 이후의 변화(분포·정책·사용자)가 파이프라인에 영향을 준다.
- 설계는 **문제 정의 → Task Type 결정 → Task Type에 따른 시스템 디자인** 순서로 간다.

### 중심은 모델이 아니라 데이터

- **"모델은 교체 가능하고, 데이터 시스템은 누적 자산"** — 모델 버전은 빠르게 바뀌고, 데이터 분포는 시간이 지나며
  변하고, 파이프라인은 장기 운영 대상이다. 실패 원인의 상당 부분이 데이터·파이프라인에서 생긴다.
- 그래서 필요한 능력은 데이터 아키텍처·시스템 디자인이다 — 큰 그림을 설계한 뒤 세부를 점검하고, 요구사항에 어떻게
  대응할지, 어떤 도구를 엮을지 정한다.

### 범위

수집부터 학습 전까지가 아니라 **데이터 시스템 전체**가 범위다:

```
데이터 시스템 설계 → 데이터 소스 정의 → 수집·적재 → 정제·표준화
  → 라벨(정답) 생성·수집 → 데이터 검증 → 학습용 데이터셋 구성(샘플링·분할) → 메타데이터·리니지 관리
```

### 데이터 소스 — 멀티 소스·멀티 레이트

| 소스 | 형태 |
|---|---|
| OLTP | 정형 |
| 이벤트 로그 | 반정형 |
| 문서·텍스트 | 비정형 |

유입 방식은 배치·스트리밍·하이브리드다. **소스마다 신뢰도와 결측·지연 특성이 다르므로 설계는 소스 특성에서
시작한다.** → [[배치 처리]] · [[스트림 처리]] · [[비정형 데이터 파이프라인]]

### 라벨은 데이터 파이프라인의 일부

라벨링은 ML 데이터 파이프라인에서 **가장 비싸고 취약한 지점**이다(분류 모델 기준).

- 라벨은 자연 발생하지 않는다.
- **라벨 정의가 바뀌면 모델의 목표가 바뀔 수 있다.**
- 라벨 생성 지연이 전체 학습 주기를 늘린다.
- **라벨 품질이 모델 성능의 상한선**을 정한다 → 라벨링 파이프라인이 필요하다.

p10은 바운딩 박스 라벨링 도구 화면(보행자·차량 객체 클래스) 스크린숏이다.

### 데이터 검증은 필수

들어오는 데이터가 정상인지 **자동으로** 판단해야 한다.

- 스키마·타입·범위·결측 검증
- 분포 요약 통계(평균·분산·분위수) 모니터링
- 이상치·급격한 분포 변화 감지

→ [[데이터 SLA]] · [[데이터 관측성]] · [[데이터 드리프트]]

### 데이터 분할(Train / Validation / Test)

- **시간 기반 분할이 필요한 경우가 많다.**
- **사용자·그룹 단위 누수**를 피해야 한다.
- 테스트는 **미래의 입력 분포**를 가정해야 한다.
- 분할 전략 자체가 성능을 과대·과소평가할 수 있다. 층화 추출(Stratified Sampling).

슬라이드 이미지는 전체 데이터를 Training ~70% · Validation ~15% · Test ~15%로 나눈 그림이다. → [[데이터 누수]]

### 메타데이터와 리니지

"이 데이터가 어떻게 생성됐는지" 추적해야 장애·품질 이슈의 원인을 찾을 수 있다.

- 데이터의 출처(소스)
- 변환 단계(누가·언제·무엇을)
- 사용된 데이터셋(어떤 버전)

→ [[데이터 거버넌스와 카탈로그]] · [[데이터와 모델 버전 관리]]

### 데이터 엔지니어의 책임

데이터 엔지니어는 **ML 데이터 생산 체계**를 설계한다 — 멀티 소스 수집 구조, 라벨 생성·수집 파이프라인, 데이터 검증
(quality gates) 내장, 데이터 버저닝·리니지 기반의 운영 가능성.

## 핵심

- **라벨을 파이프라인의 한 단계로 올린 것이 이 강의의 새 내용이다.** Part 1에서 라벨은
  [[AI DE 강의 1-13 Skew와 Drift]]에 곁가지로만 나온다 — 신선도 지표의 "라벨 도착 시간", 재학습 1단계의 "최신
  피처·라벨 로드", 데이터 엔지니어 책임의 "정답 라벨 피드백". 라벨을 어떻게 만들고 무엇이 비싼지는 다루지 않았다.
  라벨 정의 변경 = 목표 변경, 라벨 지연 = 학습 주기 연장이라는 두 관찰은 라벨을 스키마·신선도처럼 **계약과 SLA의
  대상**으로 봐야 한다는 뜻이다. *(위키의 관찰)* → [[데이터 SLA]]
- **누수는 분할 슬라이드에서 처음 등장한다.** "시간 기반 분할"과 "테스트는 미래 분포를 가정"은 결국 **학습 시점에
  미래 정보가 섞이지 않게 하라**는 요구다. 이것은 [[피처 스토어]]의 빈칸으로 남은 시점 정합성(point-in-time
  correctness) — 각 라벨 시점에 그때 알 수 있던 피처만 붙이기 — 과 같은 문제의 다른 얼굴이다. 강의는 둘을 잇지
  않는다. *(위키의 관찰)* → [[데이터 누수]]
- 검증 슬라이드의 "분포 요약 통계·급격한 분포 변화 감지"는 Part 1의 드리프트 감지와 같은 장치를 **학습 데이터
  입구**에 두는 것이다. 드리프트 감시가 서빙 쪽 출구라면 이것은 입구다. *(위키의 관찰)*

## 주의·결함

- **분할 이미지와 본문의 긴장** — 본문은 "시간 기반 분할이 필요한 경우가 많다"고 하는데, 옆 이미지는 비율(70/15/15)만
  보여 주는 일반적인 무작위 분할 그림이다. 이미지를 무작위 분할로 읽으면 본문 권고와 어긋난다. 판정할 문제는 아니고,
  읽을 때 주의할 점이다. *(위키의 관찰)*
- **p14와 p15가 거의 같다** — 문구("어떻게 생성됐는지" vs "이렇게 됐는지")와 p15에 붙은 컬럼 수준 리니지 이미지만
  다르다.
- **슬라이드 머리글이 템플릿 잔재다** — Ch3 전체 슬라이드 머리글이 Ch1 소단원 제목인 "2. AI 시대를 위한 파이프라인과
  데이터엔지니어의 진화방향"으로 되어 있다.
- 이미지 출처는 전부 블로그·2차 자료다(Medium, Privacy International, thaddeus-segura.com, MLU-Explain,
  Data Engineer Things). 1차 자료 인용은 없다.
- 라벨 파이프라인의 구체적 구현(라벨링 도구·약한 지도·사람 검수 흐름)과 데이터 검증 도구는 다루지 않는다.
