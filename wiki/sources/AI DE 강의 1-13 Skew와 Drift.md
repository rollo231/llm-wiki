## 요약

### (1) Training-Serving Skew

- 정의: 학습에 쓴 데이터·전처리 로직과 서비스 환경에 들어오는 데이터의 형태·로직이 달라 예측 성능이 떨어지는 현상.

| | 학습 | 서비스 |
|---|---|---|
| 환경 | 연구실 | 실전 운영 |
| 담당 | 데이터 사이언티스트 | 백엔드·플랫폼 엔지니어 |
| 데이터 | 과거 이력(배치) | 실시간 이벤트(스트리밍) |
| 도구 | Python·Pandas | Spark·Java·Go·C++ |
| 로직 | 복잡한 집계, 고지연 허용 | 단순화, 밀리초 |

덱이 드는 주된 원인은 언어와 환경이 달라 로직을 두 번 구현하면서 생기는 미세한 차이다.
- "침묵의 살인자": 에러 로그는 0건인데 AI는 엉뚱한 입력으로 성과를 망친다. 예: 피처 "최근 30일 평균 결제액", 이력은 구매 100만 원 · 취소 -100만 원 · 구매 2만 원.
  - 학습: 취소를 반영해 (100만 − 100만 + 2만) ÷ 1건 = 20,000원이므로 소액 구매 고객이다.
  - 서빙: 개발자가 취소 예외 처리를 빠뜨려 (100만 + 100만 + 2만) ÷ 3건 = 673,333원이 되고, VIP로 오판해 고가 상품을 추천했다가 실패한다. 덱은 "33배 뻥튀기."라고 쓴다. 추천 클릭률 1.2%(예상 5.5%), 전환율 0.3%.
- 해결은 피처 스토어로 파이프라인을 하나로 모으는 것이다. 배치 소스(DW·레이크)와 스트림 소스(Kafka·Kinesis)가 하나의 변환 로직을 거쳐 오프라인 스토어(S3·BigQuery·Snowflake, 학습용 `get_historical_features()`)와 온라인 스토어(Redis·DynamoDB·Cassandra, 서빙용 `get_online_features()`)로 간다. 도구는 Feast, Tecton, Hopsworks, Vertex AI Feature Store이고, 원칙은 "Write Once, Compute Anywhere"다.
- 실무 체크리스트: 피처 계약(스키마·윈도우 크기·예외 처리 규칙) 명문화, 학습·서빙 공통 라이브러리, 오프라인-온라인 통계 분포 모니터링.

### (2) Data Drift와 Concept Drift

- 모델에도 유통기한이 있다: 모델은 과거 데이터를 비춘 거울이라, 파이프라인이 완벽해도 현실이 바뀌면 조용히 낡는다. 덱은 성능 저하를 버그로 보지 않고 시간의 함수로 본다.
- Data Drift(공변량 변화): 입력 분포 P(X)가 학습 때와 달라진다. 코로나19: 2019년 학습 데이터에서 마스크 대량 구매는 희귀한 사기·매점매석 패턴이었는데, 2020년에는 생존을 위한 정상 행동이 되어 정상 거래를 오탐지한다. 징후: 새로운 패턴, 특정 연령층·시간대 비중 급변, 계절성.
- Concept Drift: 입력 분포는 그대로여도 정답을 가르는 기준 P(Y|X)가 바뀐다. 스팸 필터: 과거 "당첨! 100% 무료 증정"은 쉽게 잡혔지만, 지금은 "CJ대한통운 배송 안내입니다" 같은 일상 문장이 악성 링크로 이어진다. 유형: 급격한(Sudden, 락다운), 점진적(Gradual, 인플레이션), 주기적(Recurrent, 블랙프라이데이·계절).
- 원인은 외부와 내부로 나눈다.

| 외부 요인 | 내부 요인 |
|---|---|
| 팬데믹·사회적 이슈 | 마케팅 캠페인(아이돌 모델 기용으로 10~20대 급증) |
| 경기 변동·인플레이션 | 제품 UI/UX 개편(버튼 위치 변경으로 클릭 로그 패턴 변화) |
| 규제·정책 변화 | 가격 정책·서비스 변경(구독료 인상, 무료 배송 기준) |
| 계절성 | 데이터 파이프라인 변경(로깅 로직 수정, 단위 cm → m) |

### (3) 감시와 자동 재학습

- 데이터 운영 SLA 4대 축: 신선도(파이프라인 지연, 피처·라벨 도착 시간), 분포 안정성(학습 vs 서빙 분포 차이), 품질/완전성(결측·이상치·타입·스키마), 피처 일관성(학습·서빙 전처리 로직과 값의 동일성).
- 통계적 감지 지표: PSI(Population Stability Index), KL Divergence, Chi-square, KS Test. 기준 분포(학습)와 실시간 분포(서빙)를 비교한다.
- 재학습 트리거: 드리프트 임계치 초과("PSI > 0.2", KL 급증), 성능 저하(Accuracy·F1 하락), 스케줄·이벤트.
- Self-Healing 파이프라인은 5단계다.

| 단계 | 내용 |
|---|---|
| 1. 데이터 수집 | 최신 피처·라벨 로드, 품질·스키마 검증, 데이터셋 버전 관리 |
| 2. 모델 학습 | 전처리 실행, 하이퍼파라미터 튜닝, 재현 가능한 학습 환경 |
| 3. 모델 평가 | Champion vs Challenger, 오프라인 지표 검증, 공정성·편향 체크 |
| 4. 배포 | 카나리·블루-그린, 섀도우 모드 테스트, 자동 롤백 가드레일 |
| 5. 관측 | 실시간 추론 모니터링, 피드백 루프, 로그·트레이스 |

안전장치로는 무분별한 재학습을 막는 쿨다운 기간과, 고위험 모델을 배포할 때의 사람 승인(Human-in-the-loop)을 든다.
- 데이터 엔지니어의 새 역할: "배관공"에서 데이터 품질·거버넌스 지휘자로 바뀐다고 한다. 신선도·품질(신선도 SLO, 데이터 계약, 실시간 품질 검증), 피처 스토어 거버넌스(재사용·표준화, 계보 추적, 정답 라벨 피드백), 재학습 오케스트레이션(드리프트 기반 트리거, 모델 버전·메타데이터, 비용 최적화). 데이터를 내부 고객이 쓰는 제품처럼 관리한다. 목표 예: 드리프트 감지 시간(MTTD) 10분 미만, 복구·재학습 시간(MTTR) 4시간 미만.
- 다음 액션: SLA·SLO 정의(신선도 한계, 결측 허용 범위, 드리프트 임계값), 학습 데이터 기준 분포 저장과 라이브 로깅, 주요 피처 PSI 추이 대시보드·알림, 재학습 플레이북(절차·승격 규칙·롤백) 문서화.

## 핵심

- 로직 불일치형 스큐와 드리프트는 원인과 대응이 다르다. 강의의 두 절을 나란히 놓으면, (1)의 스큐는 코드가 달라서 생기고(우리가 만든 불일치이므로 로직을 하나로 모아 없앤다), (2)의 드리프트는 세상이 달라져서 생긴다(누구의 버그도 아니므로 감시하고 재학습한다). 이 대비는 로직 불일치형 스큐에만 맞는다. Google의 정의(Zinkevich 「Rules of Machine Learning」)에서 스큐는 학습과 서빙의 성능 차이이고 데이터 변화도 원인에 들어가며, Part 2의 [[AI DE 강의 2-06 Training-Serving Skew 예방]]도 Data Drift를 스큐의 원인으로 든다. 용어의 두 갈래는 [[학습-서빙 스큐]] · [[데이터 드리프트]]에 정리했다. ⚠️ 위키 정정 (2026-09-14): 처음에는 "스큐와 드리프트는 원인이 반대다"를 이 강의의 핵심으로 적었다. 인제스트 때 좁혔고, 린트에서 헤드라인도 고쳤다.
- 예시 검산: 위키가 다시 계산해 보니 20,000원과 673,333.33원, 비율 33.67배로 강의의 계산은 맞다. 다만 이 예에는 차이가 두 군데 있다. 취소의 부호(-100만 vs +100만)와 분모(순구매 1건 vs 이벤트 3건)다. 강의는 취소 누락만 원인으로 들지만, 위키가 보기에는 "무엇을 1건으로 세는가"라는 정의 차이도 그 자체로 스큐다.
- 이 스큐 문제의 대표 사례는 Google TFX 논문이다. Google Play에서 학습-서빙 스큐를 없앤 뒤 A/B 테스트에서 앱 설치율이 2% 올랐다. 같은 코스의 [[AI DE 강의 1-16 AI 파이프라인 구축 사례]]는 이 2%를 Uber 사례에 잘못 붙인다.
- 원인 표의 "데이터 파이프라인 변경(단위 cm → m)"은 세상이 바뀐 것이 아니고 우리가 바꾼 것이다. 위키의 관찰이다([[스키마 진화]] · [[데이터 드리프트]]).

## 주의·결함

- ⚠️ 재학습 트리거의 "PSI > 0.2"는 널리 쓰이는 관례(0.1 · 0.25 경계)에 없는 값이다. 정정과 출처(Yurdakul & Naranjo 2020)는 [[데이터 드리프트]]의 「PSI 임계치 — 강의 정정」에 있다.
- 같은 파트 안에서 데이터 품질 축이 세 버전이다. 이 강의의 4대 축, [[AI DE 강의 1-14 데이터 SLA와 모니터링]]의 3대 지표, [[AI DE 강의 1-16 AI 파이프라인 구축 사례]]의 5대 기둥이다. 셋의 대조는 [[데이터 SLA]]에 있다.
- 예시 수치: 클릭률 5.5% → 1.2%, MTTD 10분·MTTR 4시간, 가용성 99.9%.
- 라벨 분포 자체가 바뀌는 경우(P(Y)의 변화)는 다루지 않는다.
